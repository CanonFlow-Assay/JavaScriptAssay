# Playground convergence — phase 1

The reservation playground already demonstrates owned-property input decoding,
immutable explicit outcomes, a pure domain, executed command evidence and
retained mutation survivors. It is the JavaScript counterpart of the portable
boundary pattern, not a proof of deep immutability or a replacement for `verify`.

The next safe increment is a tiny configuration firewall at an application
adapter: map supplied settings to frozen validated data or a closed rejection.
Use the existing Node 20 compatibility lane and `npm run playground`; retain the
weak/expanded selections. Do not promote `.jsassay.json` into an app rules DSL,
make browser code authoritative, or add source generation only for parity.
